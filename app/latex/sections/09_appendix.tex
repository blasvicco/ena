\section{Information Available to Each Agent}
\label{app:information}
A comparison across agent families is only fair if no agent learns more about the environment than the others. This appendix lists everything each agent receives.

\subsection{The interface}
Every agent, ENA and the baselines alike, interacts with an environment only through the Gymnasium interface. A reset returns an initial observation. A step returns the next observation, the reward, and whether the episode terminated or was truncated by the time limit. In CartPole, the observation is the cart's position and velocity, and the pole's angle and angular velocity. In HalfCheetah, it is the torso's height and angle, the joint angles, and all their velocities, without the forward position.

The physical parameters that distinguish the environments are never part of the observation. In CartPole, these are gravity, the pole's mass and the pole's length. In HalfCheetah, they are gravity, friction, wind and the presence of air. No agent is told when the environment changes, which environment it is in, or how many environments there are. The environment names in our figures and tables come from the experiment's logs, and are used only for analysis. ENA's niches are its own numbering.

\subsection{Task constants}
ENA reads two constants from each task's Gymnasium registration: the episode time limit, and the solved threshold $R_{\text{solved}}$. They are \Res{cfg/cartpole/maxsteps} steps and \Res{cfg/cartpole/solved} in CartPole, and \Res{cfg/cheetah/maxsteps} steps and \Res{cfg/cheetah/solved} in HalfCheetah. The time limit rescales a truncated candidate return to a full-episode equivalent~\eqref{eq:plasticity}. HalfCheetah episodes never end early, and its candidates are evaluated for at most \Res{cfg/cheetah/maxeval} steps, so every HalfCheetah candidate's return is rescaled. The solved threshold is the utility scale of the specialist selection~\eqref{eq:bpr}. The selection therefore depends on this registered constant, even on HalfCheetah, where no agent reaches it. There, the threshold sets how much one return moves the belief, since the return noise of~\eqref{eq:bpr} is \Res{cfg/ena/bpr/noise} times the threshold in return units. Until \Res{cfg/ena/signal/warmup} returns of the current regime have been seen, it is also the scale against which returns are normalized for Trust. After that, Trust normalizes against the percentiles of recent returns~\eqref{eq:trust}. Both constants are public properties of the task, not of the physics. The baselines meet the same time limit through the truncation signal.

\subsection{Environment detection}
\label{sec:appendix_detection}
The detector's input is the sequence of transitions $(s_t, a_t, s_{t+1})$: the observation before acting, the action taken, and the observation after. This is exactly what the agent sees. The detector does not read the reward, the physical parameters or the environment's name. A change of physics changes how the observed velocities evolve, so the current niche's dynamics model~\eqref{eq:dynamics} predicts the new transitions worse. In the ablation, changes between the training environments are detected almost immediately and almost without error (Table~\ref{tab:detection}).

At test, the detector is frozen and creates no niches. Physics close to a known niche are recognized as that niche. The detector does not need to name an environment, only to find the closest physics it knows. Neptune's physics, for instance, are recognized as Earth's in \Res{ablation/ENA-Combined/recog/Neptune/Earth-Standard} of the \Res{ablation/n} replicates. When no niche explains the transitions within the margin $m$, the episode is left unrecognized, and no niche is assigned. The selection~\eqref{eq:bpr} still weighs every niche by how well its dynamics model explains the episode, so it falls back on the niches whose models explain the episode best.

Recognition is weaker in two cases:
\begin{itemize}
\item \textit{False alarms.} In a test phase, every confirmed change except the first one after a switch is a false alarm. In physics near the margin $m$, the detector can alternate between recognizing a niche and leaving the physics unrecognized. Each confirmation resets the selection's belief to uniform.
\item \textit{Fragmentation.} In some replicates, one training environment is split over two niches.
\end{itemize}
Table~\ref{tab:detection} gives these numbers for the two ablation variants with environment detection. For each phase, it lists the share of unrecognized episodes, the confirmed changes and the episode of the first one. For each training environment, it lists the Hall of Fame niches. Every phase except the run's first follows a real switch. At most one confirmed change per phase is therefore a detection, and the rest are false alarms. The first training phase, Mars, starts with no niche at all. The detector is also reset when the test begins, so the test's Mars phase starts without a current niche, like the run's first. The Brown-dwarf phase is mostly left unrecognized. After it, the detector recognizes Earth by identification, without confirming a change, and Earth shows zero confirmed changes at test.

\subsection{Candidate evaluation}
ENA evaluates candidate specialists in fresh instances of the current environment. The experiment's own environment factory builds them from the current environment's physical parameters. ENA passes these parameters to the factory, but uses none of them for a decision. Every candidate step counts in ENA's interaction budget. A candidate evaluation is thus equivalent to an extra episode in the current environment, with the same reset that any episodic agent has. The baselines could spend the same budget in parallel copies of the environment, as vectorized training does. What ENA does assume is a resettable copy of the current physics, in which it can run episodes other than the one being played. Such a copy is free in simulation or with a digital twin. On a physical system, it would cost real time, if it can be had at all.

\subsection{Evaluation and test}
The first-solve checks (Section~\ref{sec:forgetting_protocol}) run on a separate copy of the current environment, for every agent alike. Their steps do not count as training. At test, every agent is frozen, and Section~\ref{sec:selection} lists what still adapts in ENA. Every agent of a replicate meets the same seeded environments.

\section{Hyperparameters}
\label{app:hyperparameters}

All settings are read directly from the code the studies ran, by \texttt{src/tools/paper\_config.py}. Each value is an agent's class default, unless its study script overrides it. The values here therefore cannot drift from the code.

Table~\ref{tab:hparams_ena_cartpole} gives the settings of ENA-Combined, as built by \texttt{cartpole\_ena\_ablation.py}. All six ablation variants share them, with the relevant skills switched on or off. Table~\ref{tab:hparams_ena_cheetah} lists only the settings that differ on HalfCheetah, set in \texttt{half\_cheetah.py}.

On HalfCheetah, PPO and SAC take the settings of RL Baselines3 Zoo~\cite{raffin2020rlzoo} (Table~\ref{tab:hparams_cheetah_baselines}). Both have a separate actor and critic. PPO normalizes observations, and scales rewards by the standard deviation of the return. Two settings deviate from the zoo. PPO's learning rate is not annealed, because annealing it to zero would freeze PPO in its last environment. SAC applies its gradient steps in groups of \Res{cfg/cheetahsac/gradientsteps} every \Res{cfg/cheetahsac/updatefrequency} environment steps, for speed, which keeps the zoo's ratio of one per step.

\section{Compute Environment}
\label{app:compute}

\subsection*{CartPole experiments (all studies except HalfCheetah)}
All CartPole studies ran inside a Docker container (\texttt{hub/python/Dockerfile}) on the host machine:
\begin{itemize}
  \item \textbf{Host:} Apple MacBook Pro, Apple M1~Pro chip, 8 cores (6 performance + 2 efficiency), 16\,GB RAM.
  \item \textbf{Container OS:} Linux (ARM64, via Docker Desktop on macOS).
  \item \textbf{Cores:} the runner used 6 of the 8 cores, running up to 6 replicates in parallel, one process each. Within a replicate, the agents trained one after another, and ENA evaluated its candidates on one thread. Wall-clock times are therefore measured under this shared load.
  \item \textbf{Python:} 3.11 (Docker image \texttt{python:3.11-slim}).
  \item \textbf{Key libraries (pinned):} TensorFlow 2.21.0, Gymnasium[MuJoCo] 1.3.0, MuJoCo 3.13.0, NumPy 2.4.6, Keras 3.15.1, SciPy 1.17.1, PyWavelets 1.8.0. Full list in \texttt{app/requirements.txt}.
  \item \textbf{Seeds} (Section~\ref{sec:setup}): \Res{seeds/ablation/first}--\Res{seeds/ablation/last} for the ablation and for the Plasticity-controller and selection studies; \Res{seeds/challenge/first}--\Res{seeds/challenge/last} for the comparison with single-policy learners.
\end{itemize}

\subsection*{HalfCheetah experiment (cloud run)}
The HalfCheetah comparison ran in AWS (eu-west-1), on one \textbf{c8g.xlarge} instance per replicate, \Res{cheetah/n} instances in all:\footnote{Instance type defined in \texttt{infra/src/qos/qos.json}.}
\begin{itemize}
  \item \textbf{Instance:} AWS c8g.xlarge, 4 vCPU (AWS Graviton4, ARM64).
  \item \textbf{Container:} Linux aarch64 (ARM64 Docker image, \texttt{hub/cloud/Dockerfile}), built from the same base image and pinned \texttt{requirements.txt} as the CartPole environment.
  \item \textbf{Hardware and threads, as each replicate recorded them:} \Res{cheetah/hardware}.
  \item \textbf{Seeds} (Section~\ref{sec:setup}): \Res{seeds/cheetah/first}--\Res{seeds/cheetah/last}.
\end{itemize}
